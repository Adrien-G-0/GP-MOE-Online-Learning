Plan d'Implémentation et de Test : Sequential Gaussian Processes for Online Learning (GP-MOE)Phase 1 : Architecture globale et préparation (Setup)L'objectif de cette phase est de préparer l'environnement et les structures de données de base pour gérer des flux de données continus.Module de Données (Streaming Data) : Créer une classe pour simuler l'arrivée séquentielle des données ($x_i, y_i$) à chaque instant $i$.Structure du Modèle de Base : Définir les classes pour les composantes principales : le processus gaussien (GP) expert, les particules du Sequential Monte Carlo (SMC), et le gestionnaire global GP-MOE.Noyau (Kernel) : Implémenter le noyau RBF (Radial Basis Function) avec ses hyperparamètres (variance, échelle de longueur).+1Phase 2 : Implémentation de la Méthodologie (Task 1: Elucidate Methodologies)Cette phase est le cœur du projet. L'agent devra coder les algorithmes théoriques décrits dans l'article.Processus de Restaurant Chinois (CRP) : Implémenter la fonction d'affectation séquentielle des nouvelles observations aux clusters existants ou à un nouveau cluster, en utilisant le CRP basé sur un modèle de mélange de processus de Dirichlet.Échantillonneur par Tranches Elliptiques (Elliptical Slice Sampler - ESS) : Coder l'algorithme ESS pour mettre à jour l'état des hyperparamètres log-normaux du GP de chaque cluster sans nécessiter de calcul de vraisemblance conjuguée.Filtre Particulaire (SMC) : * Initialiser $J$ particules indépendantes.Coder la mise à jour séquentielle des poids des particules ($w_i^{(j)}$) en utilisant le ratio de vraisemblance.+1Implémenter le calcul de la taille d'échantillon effective ($N_{eff}$).Déclencher le rééchantillonnage multinomial si $N_{eff} < J/2$ pour éviter la dégénérescence des particules.Approximation Stochastique (Optionnel mais recommandé pour la scalabilité) : Ajouter une fonction de sous-échantillonnage (minibatching) de taille $B \ll N_k$ pour approximer la vraisemblance complète et maintenir la complexité computationnelle gérable.+1Phase 3 : Reproduction des Résultats Clés (Task 2: Highlight Key Findings)L'agent devra valider son code en reproduisant une expérience de base pour s'assurer que le modèle capture bien la non-stationnarité.Jeu de données de validation : Utiliser le jeu de données classique "Motorcycle crash" (qui présente un régime initial à faible bruit suivi d'un régime à fort bruit).+1Baseline : Implémenter une version simple à une seule particule pour simuler l'approche POE (Product-of-Experts).Métriques d'évaluation : Calculer l'erreur quadratique moyenne (MSE) prédictive en ligne et la log-vraisemblance prédictive (Log Likelihood) pour évaluer la quantification de l'incertitude.Visualisation : Générer un graphique montrant la moyenne prédictive, les intervalles de crédibilité à 95%, et colorer les points de données selon leur assignation au cluster (pour la particule ayant le poids le plus fort).Phase 4 : Application Pratique et Extension (Task 3: Practical Application or Extension)Pour obtenir les points bonus ("Additional credit"), l'agent devra appliquer le code à un nouveau problème et implémenter une piste d'amélioration suggérée par les auteurs.Sélection d'un nouveau jeu de données (Real-world Application) : Choisir un flux de données temporelles complexe non traité dans l'article. Suggestion : Des données de capteurs IoT industriels (par exemple, la dégradation d'une batterie où la variance du signal change à l'approche de la panne) ou un nouveau jeu de données médicales en temps réel continu.Extension Algorithmique (Creativity & Critical Thinking) : Les auteurs mentionnent deux pistes futures intéressantes. L'agent devra implémenter l'une d'entre elles :Option A (Échantillonnage Rétrospectif) : Modifier l'algorithme SMC pour inclure un échantillonnage rétrospectif des assignations de mélange $z$, car le modèle de base n'échantillonne ces indicateurs qu'une seule fois à l'arrivée de l'observation.Option B (Extension Multi-sorties) : Étendre l'approche pour modéliser conjointement plusieurs signaux en utilisant des processus gaussiens à sorties multiples (Multi-output GPs), particulièrement utile pour les scénarios de soins de santé.Test de l'Extension : Comparer les performances (MSE, temps de calcul) de l'extension algorithmique par rapport au GP-MOE standard implémenté lors de la Phase 2.Phase 5 : Rapport et Synthèse des RésultatsCompiler les résultats dans un tableau comparatif automatisé.Générer les graphiques finaux pour la présentation en classe, mettant en évidence la capacité du modèle à s'adapter aux changements soudains de dynamique dans la nouvelle application.
